=====================================================================
Guia de Integração do Back-End com o Modelo de Previsão de Atrasos
=====================================================================
0. Resumo em uma frase:
A API recebe dados brutos, aplica exatamente as mesmas transformações do treino usando artefatos salvos, executa o modelo e retorna a previsão.

---

1. Contrato de entrada (API)
A API deve receber apenas dados conhecidos antes do voo:

Input:
{
  "icao_empresa": "TAM",
  "icao_aerodromo_origem": "SBGR",
  "icao_aerodromo_destino": "SBRJ",
  "partida_prevista": "2026-02-10T14:30:00",
  "tempo_voo_estimado_hr": 1.2,
  "distancia_km": 350.3
}
Output:
{
  "previsao_atraso": 1,
  "probabilidade_atraso": 0.89
}

---

2. Carregamento do modelo (na inicialização da API)

Ao subir a API:
  carregar um único arquivo .joblib, contendo:
    modelo treinado
    OneHotEncoder
    estatísticas do Target Encoding
    ordem final das features
Esse carregamento ocorre uma única vez.

---

3. Pré-processamento do input (obrigatório)
Para cada requisição:

  3.1 Derivar features temporais
    A partir da variável "partida_prevista", derivar variáveis:
       mes
       turno

  3.2 Aplicar Target Encoding
    Converter códigos categóricos em valores numéricos:
       empresa → empresa_te
       aeródromo origem → origem_te
       aeródromo destino → destino_te
    Regra:
       se o código existir no histórico → usar valor aprendido
       se for desconhecido → usar média global
⚠️ Nunca lançar erro por categoria nova.

  3.3 Aplicar One-Hot Encoding
    Usar o OneHotEncoder carregado:
       aplicar apenas .transform()
       categorias desconhecidas são ignoradas automaticamente

  3.4 Montar vetor final
    Organizar todas as features na mesma ordem usada no treino.

---

4. Inferência

Executar para receber:
predict() → atraso (0 ou 1)
predict_proba() → probabilidade de atraso
